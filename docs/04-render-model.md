# 04 — The Normalized Render Model

Covers `ARCH-02`, and is the prerequisite for every `EXP-*` fix.

## 4.1 Why

Today the geometry of each effect is computed twice: once in `applyEffects()` as DOM style
assignments, once in `cssCode()` / `tailwindCode()` / `reactCode()` as strings. The two
implementations disagree — that is not a set of independent bugs, it is one architectural
defect with five symptoms (`EXP-01` … `EXP-05`).

Fix: **one pure function** turns state into a normalized description of what is on screen.
The preview applies it. The exporters print it. Neither one computes geometry.

```text
                    ┌──────────────┐
        state ────▶  buildRenderModel(state, env)  ────▶ RenderModel
                    └──────────────┘                        │
        ┌───────────────────────────┬─────────────────┬─────┴──────────┐
        ▼                           ▼                 ▼                ▼
  preview renderer            css exporter     tailwind exporter  react exporter
```

`env` carries only environment facts, never user intent: `{ maxLayers, reducedMotion, forExport }`.
`forExport: true` always uses the full quality layer count so a performance-capped preview never
degrades the exported code (see `08-performance.md`).

## 4.2 The model

```ts
export type RenderModel = {
  scene: SceneModel;
  glow: GlowModel | null;
  fade: FadeModel | null;
  blur: BlurModel | null;
  meta: { activeLayers: number; capped: boolean; requestedLayers: number };
};

export type SceneModel =
  | { kind: "mesh"; background: string }
  | { kind: "photo"; src: string; overlay: string; fallback: string }
  | { kind: "solid"; color: string };

/** Glow is three stacked radial nodes — the model says so explicitly. */
export type GlowModel = {
  color: string;                 // "hsl(268 90% 65%)"
  blend: "screen";
  nodes: Array<{
    role: "haze" | "bloom" | "core";
    sizePct: number;             // width as % of frame, aspect-ratio 1
    xPct: number; yPct: number;  // centre, translate(-50%, -50%)
    opacity: number;             // 0..1
    blurPx: number;              // resolved px, NOT a Tailwind class
  }>;
};

export type FadeModel = {
  /** Resolved geometry — identical for preview and export. */
  box: { top?: string; right?: string; bottom?: string; left?: string; width: string; height: string };
  gradient: string;              // full linear-gradient(...) with all eased stops
  cssDirection: "to top" | "to bottom" | "to left" | "to right";
  opacity: number;               // 0..1
  stops: Array<{ pos: number; alpha: number }>;  // for the Tailwind/React exporters
};

export type BlurModel = {
  box: { top: string; right: string; bottom: string; left: string; height: string };
  steps: Array<{
    index: number;
    blurPx: number;              // amount * ease(t), 2dp
    mask: string;                // the exact linear-gradient mask string
    maskStops: { from: number; at: number; to: number };
  }>;
  curve: CurveKey;
  amountPx: number;
  coveragePct: number;
};
```

## 4.3 Derivation rules

These are the rules the current `applyEffects()` implements implicitly. Writing them down is
most of the work.

### Glow

| Node | size | opacity | blur |
| --- | --- | --- | --- |
| `haze` | `scale * 2.2` % | `intensity * 0.50 / 100` | 48 px (`blur-3xl`) |
| `bloom` | `scale * 1.4` % | `intensity * 0.75 / 100` | 40 px (`blur-2xl`) |
| `core` | `scale * 0.7` % | `intensity / 100` | 24 px (`blur-xl`) |

All three share `left: x%`, `top: y%`, `transform: translate(-50%, -50%)`,
`aspect-ratio: 1`, `border-radius: 9999px`, `mix-blend-mode: screen`, and
`color = hsl(hue 90% 65%)`. Opacities are clamped to `0..1`.

The blur radii were implicit in Tailwind class names (`blur-3xl`/`2xl`/`xl`); the model
resolves them to pixels so exports are exact and independent of Tailwind's scale.

### Fade

```ts
const vertical = dir === "top" || dir === "bottom";
box = vertical
  ? { left: "0", right: "0", [dir]: "0", width: "100%", height: `${coverage}%` }
  : { top: "0", bottom: "0", [dir]: "0", height: "100%", width: `${coverage}%` };
```

The gradient runs *away* from the anchored edge: `DIR_CSS = { top: "to top", bottom: "to bottom",
left: "to left", right: "to right" }`, with the opaque end at the anchored edge. Stops are
generated by `fadeGradient(dir, curve, 10)`: for `i` in `0..10`, `alpha = 1 - ease(i/10)`,
`pos = i * 10 %`, colour `rgb(8 10 16 / alpha)`. The model exposes both the assembled string and
the `stops` array — exporters that cannot emit a raw gradient string (Tailwind) still need the numbers.

### Blur

```ts
const requested = layers;                                  // 1..32 from the schema
const count = forExport ? requested : Math.min(requested, env.maxLayers);
steps = range(count).map((i) => {
  const t = count === 1 ? 1 : i / (count - 1);
  const blurPx = round2(amount * ease(t));
  const pos = t * 100;
  const from = clamp(pos - 100 / count, 0, 100);
  const to   = clamp(pos + 100 / count, 0, 100);
  return { index: i, blurPx, maskStops: { from, at: pos, to },
           mask: `linear-gradient(to top, transparent ${from}%, #000 ${pos}%, transparent ${to}%)` };
});
```

The wrapper box is `inset: auto 0 0 0; height: coverage%`. Mask direction is currently hard-wired
to `to top` — if directional progressive blur is added later, it belongs here and nowhere else.

`meta.capped` is true when `count < requested`; the UI uses it to explain the performance cap,
and the exporters ignore it because they always run with `forExport: true`.

## 4.4 Invariants (make these tests)

1. **Determinism.** `buildRenderModel` is pure: same `(state, env)` → deep-equal model. No
   `Date`, no `Math.random`, no DOM reads.
2. **Preview = export.** For every state, the CSS produced by the exporter, when parsed back,
   yields the same declarations the preview renderer applied. Practically: the preview renderer
   and the CSS exporter both consume `RenderModel`, and a test asserts
   `stylesFromPreview(model)` and `declarationsFromCss(cssExport(model))` match for the shared
   property set.
3. **Layer count fidelity.** `blur.steps.length === state.blur.layers` whenever
   `forExport: true`, for all `layers` in `1..32`.
4. **Geometry fidelity.** For each of the four fade directions the exported `box` equals the
   preview `box`.
5. **Glow fidelity.** `glow.nodes.length === 3` in both preview and export.
6. **No `undefined` in output.** Every generated string is asserted free of `undefined` and `NaN`
   — this is what silently broke on an invalid `direction` or `curve`.
7. **Snapshot suite.** The three presets × three formats = nine golden-file snapshots, plus a
   property-based test over random valid states asserting invariant 6.

## 4.5 Migration path from the current file

1. Extract `CURVES`, `fadeGradient`, `maskFor` unchanged into `src/effects/curves.ts`.
2. Write `buildRenderModel` by *moving* the arithmetic out of `applyEffects()` — do not retype
   it, so the preview cannot regress.
3. Rewrite `applyEffects()` as a thin apply pass over the model (`08-performance.md` §3 covers
   doing this with CSS variables instead of full restyles).
4. Only then rewrite the three exporters against the model (`05-exporters.md`).
5. Keep the old exporters around for one commit and diff their output against the new ones on
   the presets, to make the parity gaps visible and intentional.
